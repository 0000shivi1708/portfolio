01Migration · LTIMindtree

Oracle Identity Manager to SailPoint IdentityIQ, end to end.

The enterprise ran every joiner, mover and leaver decision through OIM. IdentityIQ meant a different data model, a different rule engine, and no room for lost access.

What moved
  1. Identity modelRemapped
  2. RolesMigrated
  3. ConnectorsReconfigured
  4. Event handlers and adaptersJava and BeanShell
  5. Provisioning workflowsAutomated
How it was done
Problem
Business access depended on a legacy platform. The target used a different identity model, roles and connector framework, and cutover could not lose an account or an entitlement.
Approach
Led requirements gathering with business and technical stakeholders, mapped the identity model, migrated roles and reconfigured connectors. Where out-of-the-box connectors fell short, I built custom event handlers, adapters, schedulers and Java components.
Outcome
Zero data loss and minimal disruption at cutover. Provisioning and deprovisioning moved to automated workflows, with around 40% less manual effort.
Across the identity lifecycle

  1. Joiner

    Right access on day one, provisioned from the HR event through standard and custom connectors.

  2. Mover

    A role change recalculates access through role-based rules, event handlers and schedulers.

  3. Leaver

    Access removed everywhere, with reconciliation keeping identity data consistent.

  4. Sign-on

    Single sign-on through Oracle Access Manager and WebGate 10g; directory in Oracle Unified Directory.
